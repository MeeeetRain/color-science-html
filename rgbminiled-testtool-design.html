RGB MiniLED 电视画质测试工具 设计说明 v0.5

面向 RGB MiniLED 背光电视的 串色 与 动态画面色域缩小 两类缺陷 · 测试图卡生成 + WebUI 测试台（设备连接 · 准备 · 执行 · 结果）+ 测量分析 + 报告导出 · 指标锚定 IDMS / CIE D50 CIELAB 色域体积 + Gamut Rings
⚠ 重要：迄今未做任何真机实测。 整套系统目前只在合成显示模型上跑通——没有连过真电视，没有用 CS-2000 / CA-410 / CXC-2600 测过哪怕一次， 本文出现的所有数字（收缩率、色晕半径等）都是仿真示意值，绝对值无意义，仅用于演示管线能算出什么。 真实可信的结果要等接入真机后产生。完整的「没做 / 待办」清单见文末 第九节。

一、要解决什么问题

RGB MiniLED 把背光从"白光 + 彩膜"升级为独立驱动的 R/G/B 分区——色域与亮度大涨， 但也把"亮度型 blooming"升级成了两类新缺陷：

① 串色 / 彩色光晕 Colour Crosstalk

本质：色度的空间光晕。白点在彩色背景里发品红/发青，肤色上出现彩色镶边。

  • 背光空间分辨率 ≪ LCD 像素 → 分区背光是"折中混合色"
  • 光学串扰（PSF 侧向漏光）→ 邻区互染
  • LED 发射光谱与彩膜通带失配 → 色偏
  • 三通道局部调光反演误差

② 动态色域缩小 Dynamic Gamut Shrink

本质：色域随 APL / 背景 / 运动 收缩——静态色块漂亮、动态内容缩水。

  • 功率/热限制（ABL）→ 高 APL 下峰值彩色亮度回退
  • 局部调光色度折中 → 复杂画面到不了满饱和
  • 时序动态/压摆率 → 瞬态掉饱和、拖影
  • 动态色调/色域映射（DTM）压缩

二、测试指标

串色指标（已全部二维化）

指标定义
色串扰半径 R_cross沿剖线 Δu'v' 衰减到阈值前的最远距离，按屏宽归一 %W
二维 Δu'v' 热力图全场色度偏差分布（CXC-2600 直接出）
棋盘逐格污染各格中心被邻色污染的 Δu'v' + 污染热力图
背光 PSF FWHMR/G/B 单点点扩散半高宽（光学串扰来源）
彩色边缘 / 角落异色硬边色过冲；中心染色（VESA 黑位彩色版）

动态色域指标

指标定义
CIELAB-D50 色域体积实测壳点(RGBCMYW+黑)凸包体积，按固定峰值白点归一
BT.2020 / P3 覆盖率逐 L* 切片的环交覆盖
Gamut Rings按 L* 切片的 a*b* 截面积分布（色域示波器）
动态色域收缩率 (KPI)1 − vol(大窗/高APL) / vol(小窗/低APL)
color-in-context同色块随背景 APL 升高的掉饱和
关键设计：色域体积按固定峰值白点归一（而非逐窗白点），ABL 亮度回退就真实地表现为体积收缩。 色彩数学经 selftest 校验（含 CIEDE2000 对 Sharma 34 对参考，最大误差 5e-5）。 阈值（合格线）目前为占位，待按企标 + 真机实测重标定。

三、系统架构与数据流

契约：每张图卡的几何/目标值/测量 ROI 只在 sidecar JSON 里定义一次，生成与分析共用； 执行序列逐卡「上屏 → 测量 → 记录」，可单卡重测、按需播放。

五、WebUI 工作流

设备连接

右上状态条进入。选图卡发生器（Murideo/全屏HDMI/sim）+ 测量仪驱动，运行时连接，失败保留原驱动并红字提示。

① 准备

填被测样机（机型/模式/峰值/调光档）+ 选测试方案（5 个：动态色域×2、串色×3）。

② 执行

进入即列出全部图卡；▶ 开始测量逐卡播放，进度+预览+实时读数；点任一行单独重测；🖥 全屏HDMI 直出电视。

③ 结果

自动算 KPI（粉彩判定块）+ 图表（色域曲线/Gamut Rings/热力图/PSF）+ 明细表。

历史记录

每次结果自动持久化；列表复看，含图表。

报告导出

⬇ 自包含 HTML（图表内嵌）/ ⬇ CSV（原始读数）。

九、现状与待办（重要 · 务必先读）

✅ 已实现（代码可运行，但全部基于合成 / 模拟）

  • 图卡生成器（10-bit PQ / BT.2020，26 + 58 张，Murideo TIFF 导出）
  • 色彩 / 色域数学（selftest 通过，含 CIEDE2000 对 Sharma 34 对参考）
  • 分析算法：色域体积 / Gamut Rings / 覆盖率、R_cross、PSF FWHM、棋盘逐格污染、color-in-context
  • WebUI 工作流：设备连接 / 准备 / 执行 / 结果 / 历史 / 导出
  • 测量仪：CA-410 ✅ 真机已通（KM USB 串口协议 v1.08，本机读到真实 Lv/x/y）、FileMeter（读导出文件）、sim
  • 出图驱动：Murideo dry-run（出命令序列）、全屏 HDMI（SDR 可跑 + HDR Canvas 框架）、sim
  • 报告 HTML / CSV 导出、历史持久化

❌ 未做 / 待验证（关键缺口）

  • 未做完整真机测量活动 —— CA-410 已能真机点测，但尚未在真电视上按企标做成套测量/标定；本文示意数字仍来自合成模型，未做真机数据采集与比对
  • 图卡未真正上过机 —— 尚未经 Murideo / 播放器 / 全屏HDMI 送进真电视显示并系统测量
  • Murideo 真控未联调 —— WebSocket 命令 ID 全是 TODO（murideo_proto.py），待官方协议文档；仅验证过 dry-run 出序列
  • CS-2000 / CXC-2600 未接 —— 两个 driver 仍是桩（NotImplementedError）；CA-410 已实现（USB 串口协议）
  • HDR Canvas 输出未验证 —— rec2100-pq 在真 Windows HDR + CS-2000 下能否打到目标 nits、DWM 有无额外 tone-map，未测
  • 合格判定（PASS / FAIL）体系未做 —— 阈值全是占位（半径 8 / 15 %W、棋盘 0.004 / 0.01、PSF 3 / 6 %W、收缩率 40 / 60 %），需按企标重定 + 做成可配置 + 结果页 go / no-go 汇总
  • 二维配准未做 —— 真机 CXC 采集与图卡像素的物理配准（四角标记 / 单点同步）未实测；_fit_meta 仅按比例缩放
  • 合成模型偏简化 —— 棋盘 = 整格均匀混合、光晕 = 指数衰减、PSF = 高斯，均为定性占位；真机数据接入后绝对值才有意义
  • 动态色域时序 / 运动未做 —— 运动掉饱和（pursuit / 高速跟拍）二阶段未实现
  • 校准 / 标定流程未做 —— CS-2000 对 CA-410 / CXC-2600 的绝对色度标定系数；测量稳定等待 / 重测 / 超时未做
  • SDR 色彩管理未做 —— 全屏 SDR / 8-bit 宽色域卡的 ICC 嵌入未接
建议落地顺序：① 接 1 台真机 + 1 台仪器（先 CS-2000 点测，或 CXC-2600 二维，或先用 FileMeter 读导出）跑出 第一份真实数据、校准管线 → ② 按企标定 PASS / FAIL 阈值（可配置）→ ③ Murideo / 仪器 SDK 真控联调 → ④ HDR Canvas 真机 + CS-2000 验证 → ⑤ 运动 / 时序二阶段。 在产生真实数据之前，不要把任何数字当作样机的真实表现。
