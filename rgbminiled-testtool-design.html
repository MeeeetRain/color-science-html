RGB MINILED TEST TOOL

RGB MiniLED 画质测试工具如何测串色、动态色域、色彩体积与 LUT 校准

这是一套面向 RGB MiniLED 背光电视的本地测试台。它把图卡生成、精确输出、仪器采样、算法聚合和报告导出串成闭环，用可复测的数据解释“彩色光晕”“动态色域缩小”和“校准后色彩是否收敛”。

圆环基色串色：同色基准 + 异色背景 + D/3D 对比 动态色域：全屏 RGB 基准 + 背景小色块 DGR 色彩体积：RGBCMYW × 多亮度层 + 黑场原点 LUT：1D 灰阶线性化 + 3D 色彩立方体 输出：Murideo / 电脑 HDMI / UltraStudio 4K Mini
诚实边界：页面中的示例数值是算法说明用的模拟数据，不代表任何电视真机结论。实际 PASS/FAIL 阈值仍需按企标和真机样本重新标定。 设备状态以项目当前代码为准：CA-410 真机已通、Murideo 已连；CXC 二维相机驱动与配准流程已完成，仍待 Windows 真机验证；UltraStudio / DeckLink 输出链路已实现并可枚举/检查设备，真正出图依赖 Blackmagic Desktop Video 与 SDK 版本匹配。
Δu'v'

串色用色度距离量化

把 XYZ 转到 CIE 1976 u'v'，比较同色基准、小圆 D、大圆 3D 或目标色点之间的距离。

DGR

动态色域看面积保持率

先测全屏 RGB 基准三角 Aref，再测背景内 RGB 小色块三角 Aj，用 Aj/Aref 判断场景下的色域收缩。

L*u*v*

色彩体积看亮度层

不仅看 xy 三角，而是把不同亮度下的 RGBCMY 外边界、W 白点轨迹和黑场原点组成三维色壳。

1D+3D

校准先灰阶后颜色

先用 1D LUT 修中性轴和 EOTF，再用 3D LUT 修色相、饱和度和通道耦合。

RING CROSSTALK

圆环基色串色：用 D / 3D 尺寸对比找出背景对基色的污染

圆环方案让 CA-410 对准屏幕中心。每个圈内基色先测一张“圈内=背景”的同色基准，再把背景换成 R/G/B/C/M/Y/K/W；异色背景下测小圆 D 和大圆 3D。报告不是把大圆当成绝对正确，而是同时比较 A/A 同色基准、A/B@3D 的参考偏移，以及 A/B@D 相对 3D 的额外恶化。

1. 探头大小校准拖动圆径 D，让 CA-410 测光区完全落在圆内。
2. 同色基准inner=outer 得到该基色的本机实测参考。
3. 异色背景矩阵遍历 RGBCMYKW 背景，记录小圆 D 和大圆 3D。
4. 诊断输出报告基准偏移、尺寸额外恶化、ΔE_ITP、背景方向投影和有效色域保持率。
bias_D = distance(u'v'(A/B @ D), u'v'(A/A baseline)) bias_3D = distance(u'v'(A/B @ 3D), u'v'(A/A baseline)) size_extra = bias_D - bias_3D pair_delta = distance(u'v'(A/B @ D), u'v'(A/B @ 3D)) background_projection = project(shift_D, direction(A -> B))

完整模式约 105 张，快速模式约 60 张。黑色可做背景；近黑圈内色度不稳定，所以不作为圈内基色。

DYNAMIC GAMUT

动态色域：用有效 RGB 三角看场景背景下的小色块掉饱和

动态色域方案先全屏显示 R/G/B 三张基色卡，得到基准色域三角 Aref；再把同样 600 nit 的 R/G/B 中心小色块放进场景背景或复杂马赛克背景里测量。每个背景都会得到一组三个实测色点，连成 Aj。最终 DGRj = Aj / Aref，越接近 100% 表示该背景下的小目标色域越能保持。

标准方案使用 10 种 8-bit sRGB 场景色，代码会经 sRGB EOTF 转成 BT.2020 线性 nits，按 200 nit 背景白缩放；复杂方案在中心 1% 小色块外铺 RGBCMYW 随机马赛克，依次测 8、16、32、64 格细分度。

1. 全屏基准base_R / base_G / base_B，patch_pct=0，整屏就是 600 nit 基色。
2. 背景生成scene_patch 用 10 种场景色；scene_complex 用随机 RGBCMYW 马赛克。
3. 中心点测中心 1% R/G/B 小色块，等待输出 ack 和稳定时间后 CA-410 读取 XYZ。
4. 面积判定在 CIE 1976 u'v' 或 xy 空间算三角面积，汇总 DGR_min、DGR_worst、DGR_avg、DGR_range。
Aref = area(pt(R_full), pt(G_full), pt(B_full)) Aj = area(pt(R_scene_j), pt(G_scene_j), pt(B_scene_j)) DGRj = Aj / Aref worst_p = argmin_j distance(pt(P_scene_j), D65) DGR_worst = area(worst_R, worst_G, worst_B) / Aref DGR_min = min_j(DGRj) // 定级 DGR_avg = mean_j(DGRj) DGR_range = max_j(DGRj) - min_j(DGRj) verdict = fail if DGR_min < 0.75; warn if DGR_min < 0.90

标准动态色域共 33 张：3 张全屏基准 + 10 个背景 × R/G/B。复杂画面共 15 张：3 张基准 + 4 个马赛克细分度 × R/G/B。

模拟 DGR_min

82.4% 表示最差场景已经低于 90% 警戒线，但尚未低于 75% 失败线。

模拟 DGR_worst

78.9% 按 R/G/B 各自最靠近 D65 的最坏点重组成最小可达色域。

模拟 DGR_range

14.6 pp 说明不同场景或马赛克复杂度对小色块色域影响不一致。

COLOUR VOLUME

色彩体积：把“亮度 × 色度”堆成三维色壳

色彩体积方案在黑底上显示中心小色块，对 R/G/B/C/M/Y/W 每个测试色测多级亮度刺激。默认 11 级从 2% 到 100% peak，并加一张黑场作为色壳原点。计算时 R/G/B/C/M/Y 形成每个亮度层的色度外边界，W 用来观察白点和亮度轨迹；最终同时给出 CIELUV 色彩体积、ICtCp 感知体积，以及相对 BT.2020 / P3-D65 / BT.709 的覆盖率。

for patch in [R,G,B,C,M,Y,W]: for stim in [2,5,9,14,20,30,45,60,75,88,100] %: measure XYZ(patch, peak * stim / 100) boundary_layers = RGBCMY points grouped by stim white_track = W points grouped by stim volume_luv = ConvexHull(XYZ -> CIE 1976 L*u*v* + black_origin) coverage = Σ intersection_area(measured_slice, reference_slice) / Σ reference_slice

模拟 KPI B

1D LUT / 3D LUT

灰阶和色彩校准：先把中性轴拉直，再修整个色彩空间

1D LUT 只测 R=G=B 的中性轴，用来修 EOTF、亮度响应和白平衡；3D LUT 再测 RGB 立方体采样点，用来修色相、饱和度、色域边界和三通道耦合。项目当前会导出 1D CSV、3D `.cube` 和完整 JSON，后续可接电视写入接口或外部视频处理链。

灰阶采样快速 / 标准 / 工程密度可选。
目标 EOTF支持 gamma、sRGB、PQ 等目标曲线。
RGB cube3³ / 5³ / 7³ 稀疏立方体测色。
导出校准输出 1D、3D 和完整测量记录。

PRECISE PC HDMI OUTPUT

电脑 HDMI 精准色彩输出：不是简单网页全屏，而是原生 10-bit HDR10 输出链

项目有两条电脑 HDMI 路径。浏览器 `/display` 适合快速预览和几何联调，但经过浏览器和系统合成，只能算 best-effort。更精准的路径是 `hdmi-gpu` + `hdr-agent.exe`：Python 服务只发送屏幕描述符，原生 Agent 在指定显示器上生成 10-bit PQ 帧，并写 HDR10 元数据。

绝对 nits 描述服务端输出 bg / rects / circles，颜色为 BT.2020 绝对亮度。
PQ 逐位一致Agent 的 PQ 常量与 `rgbtool/color.py` 对齐。
10-bit 帧缓冲R10G10B10A2 打包，DXGI HDR 色彩空间输出。
ack 再测量Agent POST ack 后，服务端才触发 CA-410 / CXC 读数。
python -m webui.server --murideo hdmi-gpu --meter ca410 hdr-agent.exe --server http://127.0.0.1:8000 --output 1

前提：Windows 目标显示器开启 HDR；GPU 输出设 RGB Full / 4:4:4 / 10-12 bpc；分辨率与缩放匹配。

DEVICE LINKS

这个项目已经做到和预留了哪些设备连接

Konica Minolta CA-410

高速点测色度计，是圆环基色串色、色彩体积中心点、动态色域和 LUT 采样的主力。项目已实现 USB CDC 串口通讯、自动找端口、`MCH` 机内校准通道选择、CH00-CH99 扫描和设备页实时切换。它的优势是快：适合大量图卡序列、D/3D 圆环矩阵和灰阶 / cube 校准。

重点快速点测通道灵活
Blackmagic UltraStudio 4K Mini / DeckLink

用于原生 SDI / HDMI 输出。WebUI 选择 decklink 后由外部 Agent 轮询同一套 `current / draw / ack` 接口，把服务端图卡描述转成 10-bit RGBXLE 帧并写入 HDR metadata。重点在灵活：可切 SDI / HDMI、可选 1080p60 / 2160p30、可随每个测试方案覆盖色彩空间 / EOTF，并通过 ack 保证测量同步。当前代码已支持设备枚举和连接检查，真出图需要 Desktop Video 与 SDK 版本匹配。

重点快速换图SDI / HDMI 灵活
Murideo SEVEN G8K

通过 LAN WebSocket 控制 HDR、BT.2020、窗口图卡和发生器状态，是标准 HDR10 信号链的金标准。内置图卡适合灰阶 / window 类测试；彩色圆环、棋盘、光晕这类自定义图卡可走 TIFF 上传或电脑 / DeckLink 输出路径。

真机已连HDR10 发生器
Hopoo / EVERFINE CXC 二维成像色度计

通过 `CXColorMeterBaseDLL` 获取整场 Lv / x / y，用于棋盘污染、彩色光晕、背光 PSF 和二维热力图。项目已做驱动代码和屏幕四角配准工作流，把屏幕 ROI 映射到相机坐标，避免相机画面偏移或旋转造成采样错位；当前仍需要在 Windows 真机环境完成验证。

待 Win 真机验证配准流程
CS-2000 / FileMeter / SimMeter

CS-2000 作为光谱基准预留驱动骨架；FileMeter 用来读取第三方软件导出的 CSV / JSON / 2D numpy 数据；SimMeter 用合成显示模型跑通 UI、报告和算法，适合无硬件时演示和回归检查。

预留 / 桥接离线仿真
局域网 Pattern 主机

现场可让测量机接 CA-410，另一台电脑专门驱动电视输出。测量机只把屏幕描述符推到 Pattern 主机，再等待远端 `/display`、HDR Agent 或 DeckLink Agent ack，适合仪器和输出设备分布在不同电脑上的测试间。
