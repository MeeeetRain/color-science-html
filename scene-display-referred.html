Scene vs Display

调色是在改场景，还是在改屏幕？

同一份素材，为什么可以输出 Rec.709、P3、PQ HDR 多个"正确版本"？ Scene-referred 和 Display-referred 是理解现代色彩管理的核心钥匙。

核心理解：Scene-referred 描述的是拍摄现场或虚拟场景中的光；Display-referred 描述的是某个目标显示设备最终发出的光。

对创作者的影响：理解这条链路，你就知道什么时候该在 Scene 端调色（曝光、白平衡、合成），什么时候该在 Display 端微调。

1. Scene-referred：数字描述的是场景光

Scene-referred（场景参照）图像的每一个数值，对应的是拍摄现场或虚拟场景中的真实光线强度。它不是"这张图看起来有多亮"，而是"当时那个地方实际有多亮"。

参照对象 场景光 拍摄现场或虚拟场景
数值特点 可超过 1 保留曝光关系
常见例子 RAW, Log, ACES 线性或对数编码
适合操作 曝光/白平衡 合成、Look 开发
一句话定义

Scene-referred = 数字描述场景光

如果场景里有一盏灯是 1000 nit，阴影是 1 nit，那么 scene-referred 图像里这两个区域的数值比大约是 1000:1。这个关系在数值中被保留了，不管你后来把它显示在什么屏幕上。

Scene-linear 是线性场景光

数值与物理光强度成正比。0.5 表示"一半亮度"。例子：EXR 线性文件、ACES2065-1。问题是：要保留 14 档动态范围，需要极高位深。

Scene-referred 不一定线性

Log 编码也是 scene-referred，但它用对数压缩了高光，不是线性的。例子：S-Log3、LogC、V-Log、DaVinci Wide Gamut Intermediate。

2. Display-referred：数字描述的是屏幕光

Display-referred（显示参照）图像的每一个数值，对应的是目标显示设备最终发出的光线强度。它已经考虑了特定屏幕的亮度、色域和观看环境。

参照对象 显示器光 目标屏幕发出的光
数值特点 0–1 范围 已被压进显示范围
常见例子 Rec.709, sRGB PQ HDR 成片
适合操作 最终微调 交付检查、网页图片
一句话定义

Display-referred = 数字描述屏幕光

如果一段 Rec.709 视频里某个像素是 0.7，那它对应的就是"在 Rec.709 标准显示器上发出 70% 亮度的光"。这个数值已经不是场景里的真实亮度了——它已经经过了 tone mapping。

重要：PQ HDR 成片通常是 display-referred！虽然 PQ 码值对应绝对 nit 值，但成片已经经过了 tone mapping，被压缩到了目标 HDR 显示器的范围（如 1000 nit）。

4. Log 是 Scene-referred，但不是 Scene-linear

Log 曲线是 scene-referred 的非线性编码方式。它描述的是场景光，但用对数压缩了高光，在有限的位深内最大化保留动态范围。

Log 的核心特点
  • Scene-referred：数值参照场景光，不是屏幕光
  • 非线性：用对数压缩，不是线性比例
  • 不是最终画面：看起来灰是正常的
  • 需要转换：通过 LUT / CST / Output Transform
常见误区
  • Log 不是"灰色滤镜"或风格
  • Log 不是 display-referred
  • Log 不能直接交付
  • 不同品牌 Log 要配对应 Gamut

5. Output Transform：从场景到屏幕的翻译器

Output Transform（输出变换）是 scene-referred 到 display-referred 的关键步骤。它不是"套个风格 LUT"——它是一套完整的数学流程，把高动态范围场景"翻译"成目标显示器能正确显示的信号。

1. Tone Mapping

把场景的高动态范围压缩进目标显示器的亮度范围。比如把 14 stops 场景压缩到 100 nit SDR 或 1000 nit HDR。

2. Gamut Mapping

把工作空间的色域映射到目标显示器的色域。超出部分需要裁切或压缩。

3. 白点 / 观看环境

考虑目标环境的白点（D65）和观看条件（暗室、明亮房间等）。

4. Gamma / PQ / HLG

最终编码成目标格式：sRGB Gamma 2.2、PQ ST 2084、或 HLG BT.2100。

对创作者的影响：Output Transform 决定了"场景光"如何变成"屏幕光"。在 ACES 里叫 ACES Output Transform，在 DaVinci 里叫 Color Management / Output Transform，在 OCIO 里叫 View Transform。它们做的是同一件事。

6. 在 Resolve 里它们怎么落地

DaVinci Resolve 支持两种主要思路：Display-referred 直接调色，和 Scene-referred 工作流。理解它们的区别，才能选择正确的工作方式。

Scene-referred 工作流

S-Log3 → DWG Intermediate → 调色 → Output

  • 输入：S-Log3 / S-Gamut3.Cine
  • 工作空间：DaVinci Wide Gamut Intermediate
  • 调色：在 DWG 里做曝光、白平衡、Look
  • 输出：Output Transform → Rec.709 / P3 / HDR
优势：一份 master 可以输出多个版本，后期空间最大，适合复杂制作。
Display-referred 工作流

S-Log3 → Rec.709 LUT → 在 Rec.709 里调色

  • 输入：S-Log3 + 官方 Rec.709 LUT
  • 工作空间：直接是 Rec.709
  • 调色：在 Rec.709 里直接调色
  • 输出：Rec.709 直接交付
优势：简单直接，适合快速交付 SDR 视频，不需要复杂色彩管理。

9. 常见误区

误区 1：Log 就是灰色滤镜。
正解：Log 是场景参照编码，不是最终画面。灰色是它的设计特性——把高光和阴影信息"藏"在中间调，等待后期释放。
误区 2：Scene-referred 一定更高级。
正解：它适合复杂制作和多输出，但快速交付用 display-referred 也合理。选择取决于项目需求，不是"高级"与否。
误区 3：套 LUT 就等于色彩管理。
正解：LUT 可能只是显示变换，也可能包含创意风格。必须知道它在链路中做什么——是技术转换还是创意调色。
误区 4：Rec.709 调色一定错。
正解：如果目标就是 SDR 快速交付，Rec.709 display-referred 工作流完全可以成立。不要为了"专业"而复杂化。
误区 5：HDR 就一定 scene-referred。
正解：PQ HDR 成片通常是 display-referred，因为 PQ 码值对应绝对 nit。HDR 的"高动态"来自显示能力，不是编码方式。
